DBMS Concepts & Project Architecture

A comprehensive breakdown of relational database design, SQL queries, and technology integration used in the Smart Quiz project.

🗄️ 1. Database Schema & Tables

The smart_quiz database is designed following relational database management principles with four normalized tables:

  • categories: Stores the 6 quiz domains (Java, Python, MySQL, DBMS, History, Science) with unique codes and descriptions.
  • questions: Stores question texts, 4 multiple-choice options (A, B, C, D), the correct option, and educational explanations. Linked to categories via a Foreign Key.
  • users: Stores simple student registrations (ID and student name). No passwords or unnecessary PII required.
  • quiz_results: Stores completed quiz attempts including score (out of 10), percentage, date/time, and foreign keys linking to users(id) and categories(id).
-- Entity-Relationship (ER) Relational Mapping: categories (id [PK], name, code, description, icon, created_at) │ ├── (1:N) ──> questions (id [PK], category_id [FK], question_text, │ option_a, option_b, option_c, option_d, │ correct_option, explanation, difficulty) │ └── (1:N) ──> quiz_results (id [PK], user_id [FK], category_id [FK], score, total_questions, percentage, completion_date) ▲ │ (1:N) users (id [PK], student_name, created_at)

🔑 2. DBMS Keys & Normalization Concepts

This project demonstrates key database management concepts taught in the 11th-grade syllabus:

  • Primary Key (PK): Columns like categories.id, questions.id, users.id, and quiz_results.id use auto-incrementing integers to uniquely identify each row without allowing NULL values.
  • Foreign Key (FK): questions.category_id refers to categories.id, and quiz_results.user_id refers to users.id. Referential integrity is strictly maintained with ON DELETE CASCADE.
  • Normalization:
    • 1NF (First Normal Form): All column values are atomic (single-valued), and every row is unique.
    • 2NF (Second Normal Form): Meets 1NF, and all non-key attributes are fully dependent on the primary key (no partial dependencies).
    • 3NF (Third Normal Form): Meets 2NF, with no transitive dependencies (student names live in users, not duplicated inside quiz_results).

⚡ 3. SQL Queries Used in the Application

All database interactions utilize secure, parameterized queries to prevent SQL Injection vulnerabilities:

-- 1. Fetching random questions for an attempt without exposing answers: SELECT id, category_id, question_text, option_a, option_b, option_c, option_d FROM questions WHERE category_id = %s ORDER BY RAND() LIMIT 10; -- 2. Secure server-side answer retrieval for evaluation: SELECT id, correct_option, explanation FROM questions WHERE id IN (%s, %s, %s, ...); -- 3. Inserting student attempt result: INSERT INTO quiz_results (user_id, category_id, score, total_questions, percentage) VALUES (%s, %s, %s, %s, %s); -- 4. Joining tables for the Leaderboard / History view: SELECT r.id, r.score, r.total_questions, r.percentage, r.completion_date, u.student_name, c.name AS category_name FROM quiz_results r JOIN users u ON r.user_id = u.id JOIN categories c ON r.category_id = c.id ORDER BY r.completion_date DESC LIMIT 30;

💻 4. Technologies & Implementation Rationale

  • Frontend (HTML, Vanilla CSS, JavaScript): No heavy frameworks (React/Vue/Tailwind) were used. Hand-crafted clean styling ensures the project runs on any standard web browser instantly.
  • Backend (Python Flask): Python Flask is lightweight, readable, and standard for school computer science projects. Handles session management, route dispatching, and secure answer evaluation.
  • Java Subject Category: Java is provided as a prominent beginner-friendly quiz topic (covering OOP, syntax, types, and loops) so students can test their Java knowledge while keeping the web backend clean in Python.
  • Dual Database Engine Support: The project includes native MySQL connection drivers (PyMySQL) and an automatic SQLite fallback. This guarantees that evaluators can run the project effortlessly on any laptop even if a local MySQL daemon is not currently active!
